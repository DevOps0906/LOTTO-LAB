# ADR-0006 앱 광고는 P1 Android에만 AdMob 하단 배너·보상형(선택)으로 넣고, 전면 광고는 쓰지 않는다

- 상태: 제안
- 날짜: 2026-11-12

| 항목 | 내용 |
|---|---|
| 맥락 | 유료 플랜(Plus·Pro)은 P2라 그 전 수익원이 없다([01_PRD.md#4](../01_PRD.md)). 광고는 수익원이지만 복권 앱이라 도박·복권 광고, 과대 표현, 공식 오인, Google Play 도박 정책, 개인정보(광고 식별자) 위험이 함께 온다. P0 리텐션 측정도 광고로 오염되면 안 된다. |
| 선택 | ① 단계 P1, Android만(Capacitor AdMob 플러그인 — 정확한 플러그인·버전·라이선스는 착수 시 `secscan license`). Windows·웹 랜딩은 광고 없음. ② 형식: 하단 고정 배너는 M-01 홈·M-04 통계·M-16 회차 목록만. 생성·판정·입력 폼·운세·결제 화면 제외. 하단 탭·스낵바·주요 버튼과 겹치지 않음([DESIGN.md 4.8](../../DESIGN.md)). 보상형은 사용자가 고를 때만(예: 고급 통계 1회 열람). 전면 광고 금지. ③ 정책: AdMob 차단 카테고리에서 도박·복권·사행성 전부 차단, 미성년 대상 설정(child-directed·under-age) 끔. 광고 콘텐츠 최대 등급은 미결(Q8). ④ 동의: 첫 실행 시 UMP 동의(M-20, M-05 통과 후), 거부 시 비맞춤 광고, 개인정보 처리방침에 광고 식별자 기재. ⑤ 수익: Plus 이상은 광고 제거. 광고 수익은 가설이며 측정한 뒤 산정한다(bm-calc 미사용). ⑥ 측정: P0에는 광고 없음. 광고 도입 전후 리텐션(D7)을 비교한다. |
| 대안 | ① 전면 광고: 생성·판정 흐름을 끊고 스토어 정책 위험이 큼 → 기각. ② P0부터 광고: 리텐션 측정 오염 → 기각. ③ Windows·웹에도 광고: 데스크톱 광고 SDK와 정책 검토가 추가로 필요하고 랜딩은 검증용 → 기각. ④ 광고 없이 유료만: P2 전까지 수익 0 → 기각(Q9 결과에 따라 팀장 재검토). |
| 결과 | 얻음: P2 전 수익 가설 검증, Plus 광고 제거라는 결제 동기. 잃음: 새 SDK(의존성·노출 면), 광고 식별자 처리와 동의 화면, 정책 위반 시 앱 삭제 위험(Q9). 되돌리기: 플러그인 제거와 슬롯 비렌더로 끝나 비용이 낮다(데이터 모델 변경 없음). |

## 위협 메모 (광고 SDK — 노출 면)
| 항목 | 내용 |
|---|---|
| 노출 면 | 앱 → Google 광고 네트워크(요청·노출·클릭 추적), 제3자 광고 크리에이티브 렌더, UMP 동의 양식 |
| 인증·인가 | 없음(공개 광고 요청). 앱 권한·Supabase 세션과 분리 |
| 다루는 데이터 | 광고 식별자(AAID)·동의 상태·기기 정보(SDK 수집). 저장 번호·계정·이메일은 광고 요청에 넣지 않음 |
| 필요한 키·권한 | AdMob 앱 ID·광고 단위 ID — 비밀 아님(앱 번들 허용). 저장소에는 Google 테스트 ID만, 운영 ID는 빌드 시 주입. AdMob 계정 로그인은 사용자만 |
| 입력 | 신뢰할 수 없는 광고 콘텐츠. 앱 WebView에 광고 도메인을 띄우지 않음. CSP·`allowNavigation` 영향은 착수 시 확인(팀장 결정 필요) |
| 체인 | 광고 클릭 → 외부 사이트(도박·피싱) → 카테고리 차단 + 시스템 브라우저/SDK 처리로 차단 |
| 피해 범위 | 광고 슬롯·외부 이동까지. 앱 데이터·키 접근 없음 |
| 남용 | 보상형 반복 시청 → 보상은 1회 열람만, 무한 보상 금지 |
| 로그 | 광고 식별자·동의 원문을 앱 로그·크래시 리포트에 남기지 않음 |
| 결정 | 위 ①~⑥ + 출시 전 Q8·Q9 확인 전에는 광고 빌드를 배포하지 않음 |
