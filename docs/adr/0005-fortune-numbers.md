# ADR-0005 운세·테마 번호는 기기에서 결정적으로 생성하고, 사주 프로필만 회원 동의 후 저장한다

- 상태: 채택
- 날짜: 2026-11-12

| 항목 | 내용 |
|---|---|
| 맥락 | 경쟁 서비스 다수가 생년월일·띠·별자리·꿈으로 "오늘의 번호"를 준다([benchmark.md#운세·테마 번호](../benchmark.md)). 재미 기능이지만 생년월일시는 개인정보이고, '맞춤 당첨' 류 표현은 금지 문구([01_PRD.md#6](../01_PRD.md))와 충돌한다. 게스트 사용(D6)과 기기 실행 원칙([ADR-0002](0002-engine-on-device.md))도 지켜야 한다. |
| 선택 | ① 공유 패키지 `packages/fortune-engine`(순수 TS, 기기 실행)이 입력→결정적 시드(입력+날짜, 같은 날 같은 결과)→`lotto-engine`으로 6개 생성, 고정 번호와 조합. ② 테마 번호(비회원 가능): 별자리 12궁·띠 12지·생년월일·기념일 숫자·행운 숫자(=기존 고정 번호)·꿈 키워드(사전 매핑). 입력값은 서버로 보내지 않고 저장하지 않는다. ③ 사주 번호(회원 전용, P1): 생년월일·양/음력·태어난 시각(선택) → 천간지지·오행 → 같은 시드 규칙. 프로필은 동의 후 owner-only RLS 테이블 `fortune_profiles`에 저장, 계정 삭제 시 파기, 성별 등 불필요 항목 미수집. 로그인 세션 없으면 진입 차단+가입 유도. ④ 결과는 기존 generated 상태 그대로, 출처 `method`만 추가(random/condition/zodiac/birthday/dream/saju). ⑤ 모든 운세 화면에 "재미·참고용, 전통 상징 해석이며 당첨 확률과 무관" 고정 표기. |
| 대안 | ① 서버 계산: 생년월일시가 서버로 가고 오프라인 불가 → 기각. ② 사주도 게스트 허용·로컬 저장만: 기기 간 프로필 재사용 불가, 회원 가치 없음 → 기각(팀장 결정). ③ 매번 무작위: "오늘의 번호" 재현성이 없어 같은 입력에 결과가 계속 바뀜 → 기각. ④ AI 해몽: AI 키·위협 메모 필요 → P2로 미룸. |
| 결과 | 얻음: 오프라인·즉시 생성, 테마 입력값 서버 수집 0, 모바일·Windows 동일 결과. 잃음: 음양력 변환용 새 의존성(라이선스 확인 필요, GPL·AGPL 거부), 매핑 사전·엔진 수정은 앱 업데이트 필요, `fortune_profiles`라는 민감 데이터 저장 면 추가. 되돌리기: 엔진은 순수 함수라 교체 쉬움, 프로필 테이블은 삭제 마이그레이션으로 제거 가능(비용 낮음). |

- 확률 고지: 어떤 방식이든 각 번호의 당첨 확률은 같다. 운세 결과는 추천 번호(generated)일 뿐 구매·당첨 이력이 아니다(AGENTS.md 4장).
