# ADR-0002 번호 생성 엔진은 기기에서 실행한다

- 상태: 채택
- 날짜: 2026-11-12

| 항목 | 내용 |
|---|---|
| 맥락 | 번호 생성은 가장 자주 쓰는 기능이다. 게스트도 쓸 수 있어야 하고(D6) 오프라인·즉시 응답이 필요하다. 서버 계산은 호출 비용과 지연, 로그인 의존을 만든다. |
| 선택 | 로또·연금 엔진을 순수 TypeScript 패키지(`packages/lotto-engine` · `pension-engine` · `lottery-core`)로 두고 `app-core`가 기기에서 동기 호출한다(D4). 엔진은 네트워크·저장소·시간에 접근하지 않고 난수 원천을 주입받는다. 당첨 판정도 `lottery-core`의 단일 함수로, P0은 기기에서 공개 회차 데이터로 판정하고 P1 로그인 사용자는 A-09가 같은 함수로 서버 판정·이력·푸시를 맡는다. 서버는 저장·회차 공개 데이터·통계 캐시·P1 판정만 맡는다. |
| 대안 | ① 서버(Edge Function) 생성: 오프라인 불가·호출 비용으로 기각. ② 기기·서버 이중 구현: 결과 불일치 위험으로 기각. ③ Python 엔진 공유: 기기 실행 불가로 기각. |
| 결과 | 얻음: 즉시·오프라인 생성, 서버 비용 0, 모바일·Windows 동일 결과. 잃음: 엔진 수정은 앱 업데이트 필요(모바일은 스토어 심사), 엔진 로직이 클라이언트에 공개됨. 통계 입력은 마지막 동기화 데이터 기준. 되돌리기: 엔진이 순수 함수라 Edge Function으로 옮기기 쉬움(비용 낮음). |

- 판정 함수는 하나(기기·서버 공용, R1). 관련: [02_ARCHITECTURE.md#3 DF-1·DF-5](../02_ARCHITECTURE.md) · [ADR-0003](0003-supabase-rls-edge-function.md)
