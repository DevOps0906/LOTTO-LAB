# ADR-0004 PC(Windows·웹)는 모바일 시안의 시각 언어를 그대로 쓰고 배치만 바꾼다

- 상태: 채택
- 날짜: 2026-11-12

| 항목 | 내용 |
|---|---|
| 맥락 | 사용자는 모바일 시안(`design/reference/m-*.png`: 그라데이션 히어로·색 번호 공·로또/연금 카드·이번 주 요약·번호 생성 CTA)은 마음에 들어 하고 PC 화면은 마음에 들지 않는다. 원인은 레이아웃 방향보다 완성도 차이다. PC(`design/shots/D-01-1440.png`)는 회색 구조 와이어프레임뿐이고, D-01은 KPI 4개 + 막대 차트로 관리자 대시보드처럼 짜여 있다. |
| 선택 | **시각 언어는 하나(모바일 시안 기준), 레이아웃만 구간별로 다르게.** 히어로 그라데이션·번호 공·상품 카드·요약 리스트·주 CTA는 3구간 모두 같다. 1200~는 사이드바 + 2~3열 그리드(홈: 히어로 한 줄 전체, 아래 [최근 회차 + 상품 카드 2개 \| 이번 주 요약 + CTA] 2열), 768~1199는 아이콘 레일 + 2열(기존 유지). D 화면은 대응 M 화면의 컴포넌트를 재사용하고 PC 전용 컴포넌트는 만들지 않는다. 토큰은 바꾸지 않는다(`packages/design-tokens/tokens.css` 그대로). |
| 근거 | ① 토스는 디자인 시스템 하나(TDS)로 모바일과 PC를 함께 운영하고, PC 전용 비교 박스 같은 넓은 화면 패턴만 더한다. ② 화면 공유 비용: `packages/ui` 공유([ADR-0001](0001-capacitor-tauri-shared-core.md))와 맞물려 디자인·구현을 한 벌로 유지한다. |
| 대안 | ① 중앙 480px 고정(모바일 화면을 PC 가운데 그대로): 넓은 화면의 비교·표 이점을 버려 기각. ② PC 전용 디자인(대시보드형 별도 시각 언어): 디자인·컴포넌트가 두 벌이 되고 현재 PC 안이 사용자 불만의 원인이라 기각. |
| 결과 | 얻음: 3구간 일관된 인상, 컴포넌트 1벌. 잃음: D-01의 KPI·차트 중심 구성은 우측 열 작은 카드로 축소. 후속: PC 시안 D-01·D-02 hi-fi(`design/reference/d-home.html`·`d-lotto.html`)를 사용자가 확정하면 PC 정본으로 삼는다([tasks/README.md](../../tasks/README.md) task-006a). |
